TRADER — DEV & DEPLOYMENT NOTES
================================

Prerequisites on the server: Node 20+, pnpm (`corepack enable`), PostgreSQL,
nginx, an OpenAI API key, an Alpha Vantage API key.


1. LOCAL DEVELOPMENT
---------------------

    pnpm install
    cp .env.example .env        # fill in DATABASE_URL + both API keys
    pnpm db:migrate              # apply schema to Postgres

Run both dev servers, each in its own terminal:

    pnpm dev:api      # http://localhost:4000
    pnpm dev:web      # http://localhost:5173 (vite dev proxy forwards /api to :4000)


2. PRODUCTION BUILD
--------------------

    pnpm install --frozen-lockfile
    pnpm build

This builds every package and produces:

    apps/web/dist/     — static frontend, serve directly with nginx
    apps/api/dist/      — compiled API, run with `node dist/index.js`


3. RUNNING THE API IN PRODUCTION (PM2)
-----------------------------------------

Put production values in .env at the repo root (same shape as .env.example):

    NODE_ENV=production
    PORT=4000
    DATABASE_URL=postgresql://...
    OPENAI_API_KEY=...
    ALPHA_VANTAGE_API_KEY=...
    AI_DAILY_BUDGET_USD=2

Apply migrations once against the production database:

    pnpm --filter @trader/db migrate

Install PM2 if it isn't already on the box:

    npm install -g pm2

The repo includes ecosystem.config.js at the root, which points PM2 at
apps/api/dist/index.js and loads the root .env via Node's native
--env-file flag (needs Node 20.6+ — anything reasonably recent is fine,
no extra dependency required). Start it from the repo root:

    pm2 start ecosystem.config.js
    pm2 save            # persists the process list across reboots
    pm2 startup          # prints a one-time command to run so PM2 itself
                          # starts on boot — run what it prints, once

Useful commands:

    pm2 status
    pm2 logs trader-api
    pm2 restart trader-api
    pm2 stop trader-api


4. NGINX
--------

The frontend calls the API via relative "/api/..." paths, so serving both
through the same nginx origin means no CORS config or VITE_API_BASE_URL is
needed — just proxy /api to the Node process and serve the built static
files for everything else. Client-side routes (e.g. /watchlists/:id) need
the try_files fallback to index.html or a page refresh will 404.

    server {
        listen 80;
        server_name trader.example.com;   # <- change this

        root /opt/trader/apps/web/dist;
        index index.html;

        location / {
            try_files $uri /index.html;
        }

        location /api/ {
            proxy_pass http://127.0.0.1:4000;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }

        gzip on;
        gzip_types text/css application/javascript application/json;
    }

Once this serves correctly over plain HTTP, add TLS with:

    sudo certbot --nginx -d trader.example.com


5. REDEPLOYING AFTER A CHANGE
-------------------------------

    git pull
    pnpm install --frozen-lockfile
    pnpm build
    pnpm --filter @trader/db migrate     # only if the schema changed
    pm2 restart trader-api
    # nginx serves the new apps/web/dist automatically — no nginx restart needed
